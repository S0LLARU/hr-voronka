# Техническое задание на разработку внутренней системы «Воронка найма»

## 1. Общая информация

**Название проекта:** Внутренняя HR-система «Воронка найма»

**Цель системы:**  
Создать внутренний веб-сервис для автоматизации полного цикла подбора и оформления сотрудников:

**Заявка на подбор → согласование HR → согласование Finance → одобрение CEO → разрешение на поиск → назначение рекрутера → публикация вакансии → подбор → кандидат → стажировка → оформление → onboarding → уведомление Finance → постановка сотрудника в ФОТ.**

Система должна минимизировать ручную передачу информации между руководителями, HR, Finance, CEO и IT, а также фиксировать ответственного и статус на каждом этапе.

## 2. Роли пользователей

В системе должны быть следующие роли:

### 2.1. Руководитель отдела/ Инициатор

Может:

- создавать заявку на подбор
- просматривать свои заявки
- видеть статус заявк
- дополнять заявку при возврате на доработку
- просматривать кандидатов на своей вакансии
- давать обратную связь по кандидатам
- принимать решение по кандидату после стажировки

### 2.2. HRD

Может:

- просматривать все заявки
- проверять заявки
- возвращать заявки на доработку
- передавать заявки Finance
- создавать/редактировать вакансии
- вести кандидатов
- запускать onboarding
- контролировать чек-листы
- оформлять сотрудника
- запускать уведомление Finance
- видеть все вакансии
- распределять вакансии между рекрутерами
- назначать ответственного рекрутера
- контролировать сроки закрытия
- видеть общую воронку
- контролировать эффективность рекрутеров

### 2.4. Рекрутер

Может:

- видеть назначенные ему вакансии
- переводить вакансию в статус «В работе»
- фиксировать публикацию вакансии
- добавлять кандидатов
- вести кандидатов по этапам
- прикреплять резюме, портфолио и тестовые
- фиксировать результаты интервью
- формировать оффер
- переводить кандидата на стажировку

### 2.5. Finance/ Финансовый директор

Может:

- видеть заявки, требующие согласования
- видеть предлагаемую зарплату и бюджет
- согласовывать/отклонять заявку
- получать уведомление о новом официально оформленном сотруднике
- подтверждать внесение сотрудника в ФОТ/бюджет

### 2.6. CEO

Может:

- видеть заявки, прошедшие HR и Finance
- одобрять или отклонять открытие поиска
- видеть ключевую информацию по вакансии

### 2.7. IT

Может:

- видеть задачи по подготовке рабочего места
- получать информацию о новом сотруднике
- отмечать подготовку техники и доступов
- закрывать IT-задачи

### 2.8. Администратор?

Может:

- управлять пользователями
- назначать роли
- управлять справочниками
- настраивать права доступа
- просматривать журнал действий

- статус

- дату выполнения
- комментарий

## 16. Контрольный этап 3-й день стажировки

На 3-й день система автоматически отправляет уведомление непосредственному руководителю и HRD:

**Необходимо принять решение по стажировке**

Руководитель выбирает:

**«Нанимаем»**

→ запуск официального оформления.

**«Не продолжаем»**

→ кандидат переводится в статус «Отказ после стажировки».

**«Продлить стажировку»**

→ указывается новый срок и причина.

Поле:

**Комментарий руководителя обязательно.**

**HRD**

- новая заявка

- Finance согласовал
- CEO согласовал
- кандидат одобрен
- кандидат выходит
- не закрыт чек-лист
- сотрудник оформлен
- новая вакансия
- требуется назначить рекрутера
- просрочена вакансия
- требуется решение по подбору

**Рекрутер**

- назначена новая вакансия
- приближается срок закрытия
- назначено интервью
- кандидат получил/сдал тестовое
- кандидат одобрен руководителем

**Руководитель**

- кандидат отправлен на рассмотрение
- требуется ОС
- необходимо принять решение по стажировке
- сотрудник выходит

**Finance**

- новая заявка на согласование
- новый оформленный сотрудник
- требуется учесть сотрудника в ФОТ

**CEO**

- новая заявка на согласование

## 22. Система напоминаний

Необходимо реализовать автоматические напоминания.

Например:

**Если руководитель не дал ОС по кандидату 24 часа:**

🔔 Напоминание: необходимо дать обратную связь по кандидату.

**Если Finance не согласовал заявку 24 часа:**

🔔 Ожидается согласование заявки на подбор.

**Если CEO не рассмотрел заявку:**

🔔 Ожидается решение по открытию позиции.

**Если рекрутер не взял вакансию в работу:**

🔔 Вакансия ожидает начала поиска.

Сроки напоминаний должны быть настраиваемыми администратором.

**Руководитель:**

видит свои заявки и своих кандидатов.

**Рекрутер:**

видит назначенные ему вакансии.

**HRD:**

видит все вакансии и кандидатов.

**Finance:**

видит финансовую информацию и заявки, требующие согласования.

**CEO:**

видит заявки, требующие финального согласования.

**IT:**

видит только IT-задачи по сотрудникам.

## 27. Основная логика системы

Ключевой принцип:

**Нельзя перейти к следующему этапу без выполнения предыдущего обязательного этапа.**

Например:

**Нельзя начать поиск, если CEO не одобрил вакансию.**

**Нельзя передать кандидата на стажировку, если руководитель его не одобрил.**

**Нельзя завершить onboarding, если обязательные задачи не выполнены.**

**Нельзя закрыть вакансию, пока сотрудник не оформлен и Finance не подтвердил постановку в ФОТ.**

## 30. Важное требование к системе

Система должна быть построена как **единый workflow**, а не как отдельные страницы.

Каждый следующий этап должен автоматически запускаться после завершения предыдущего.

Например:

**CEO нажал «Одобрить» → HRD получает уведомление задачу назначить рекрутера → рекрутер получает вакансию → после публикации меняется статус → после выбора кандидата запускается подготовка выхода → после оформления Finance автоматически получает уведомление.**

Таким образом, информация не должна повторно вводиться разными сотрудниками.

## 32. Результат работы системы

После внедрения любой сотрудник должен понимать:

**Кто инициировал подбор → кто согласовал → кто отвечает за вакансию → где сейчас кандидат → что нужно сделать → кто должен это сделать → когда сотрудник выходит → оформлен ли он → сообщил ли HR Finance → внесён ли сотрудник в ФОТ.**

Главный результат исключить потерю информации между руководителем, HRD, рекрутером, Finance, CEO и IT и сделать весь процесс найма прозрачным и контролируемым.
