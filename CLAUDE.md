# Воронка найма — контекст для Claude

Внутренняя HR-система. Руководитель создаёт заявку на сотрудника и видит, где она, кто её держит и каких кандидатов нашли. HRD, рекрутер, Finance, CEO и IT делают свой шаг прямо в заявке. ТЗ — `docs/TZ.md`. Решения и их причины — `docs/SOLUTION.md`. Что сделано и чего нет — `README.md`.

## Как работаем

- Пиши по-русски, короткими ясными предложениями. Пользователь пишет разговорно и голосом. Перед крупным решением он хочет услышать план и варианты, потом выбирает.
- Дизайн — по стандарту команды: репозиторий `S0LLARU/standart_for_product_design`. Порядок работы — скилл `design-make`, проверка — скилл `design-check` отдельным агентом по скриншотам. Обязательно смотри `checklists/AI_TELLS.md` (признаки ИИ-дизайна) и `guides/SCREENS.md` (движение, телефон, проверка глазами).
- Стиль — **не macOS**, своё спокойное рабочее оформление:
  - шрифт Golos Text (кириллица, ровные цифры);
  - нейтральная серая основа;
  - один синий — для действия и «вашего хода»;
  - красный — только для просрочки и отказа;
  - без градиентов, стекла, теней по умолчанию, цветных точек статусов и подписей-инструкций.
- Продукт объясняет себя формой: не добавляй пояснительный текст там, где хватает формы и состояния. Упрощение не должно переносить сложность в память человека.
- После каждой правки смотри результат в браузере: десктоп 1440×900, телефон 390×844. Прогоняй `tests/flow.js` — это весь путь заявки по ролям.
- Ветка работы `claude/peaceful-bell-3h2l87`. Ветки `main` пока нет. Её создают, только когда попросит пользователь (например, для Vercel).

## Ключевые решения (не пересматривать без пользователя)

1. **Доска — это заявки, а не кандидаты.** Так решил пользователь: воронка нужна руководителю, чтобы видеть свою заявку, и HR, чтобы её вести.
2. **Пять колонок** — фазы: Согласование · Подбор · Выход · Оформление · Закрыто.
   - Шаги внутри фазы видны на карточке: полоса (пройдено / текущий / впереди) и строка «кто держит и сколько ждёт».
   - 17 статусов ТЗ разложены по этим фазам. Точный статус написан в заявке.
3. **Карточки не перетаскиваются.** Их двигают решения людей, поэтому никто не перепрыгнет через согласование (п. 27 ТЗ). Сделанный шаг сам переносит карточку, и это видно по движению (FLIP через Motion).
4. **Своя строка на карточке.** Если ход того, кто смотрит, строка синяя и называет действие («Согласовать заявку»). Иначе — кто ждёт и сколько. Просрочка — красным со значком. Срок решения по умолчанию — сутки (`Model.SLA`).
5. **Статусы вакансии** «Кандидат выбран / Стажировка / Оформление / Передано в Finance» не ставятся руками. Они вычисляются из того, где выбранные кандидаты.
6. **Заявка на несколько человек** стоит в «Подборе», пока не выбраны все. Путь каждого выбранного — отдельный блок в заявке.
7. **Кандидаты внутри заявки.** Этапы: Новые (со скринингом) → Интервью HR → Тестовое (можно пропустить) → Руководитель → Оффер.
   - «Одобрен» — это решение руководителя, а не этап.
   - Отказ — с любого этапа, с причиной; кандидат уходит в свёрнутую группу «Отказы».
8. **Возврат и отклонение** — только с комментарием. Перед подтверждением написано, к чему приведёт решение.
9. **Права по п. 23 ТЗ:**
   - руководитель — свои заявки;
   - рекрутер — назначенные ему;
   - HRD — все;
   - Finance и CEO — дошедшие до них;
   - IT — только подготовка рабочего места.
   Зарплату не видит IT, кандидатов не видят Finance, CEO и IT. Вход в прототипе заменяет переключатель «Смотрю как».

## Допущения, которые нужно подтвердить у авторов ТЗ

- HR в ТЗ = HRD: он принимает заявку и назначает рекрутера.
- Оффер даётся до стажировки, как в порядке этапов ТЗ.
- Чек-листы первого дня (п. 15) и onboarding (п. 18) повторяют часть пунктов. Пока оставлены как в ТЗ.
- В ТЗ есть статус «В работе» (п. 10), которого нет в списке 17 статусов. У нас он есть.
- «Вакансия отменена» и «Позиция больше не требуется» сведены в один статус: «Отменено» с причиной.

## Устройство кода

Статика без сборки: React 18 через htm, Motion для анимаций. Всё лежит в `vendor/`, CDN нет. Данные хранятся в localStorage.

- `js/model.js` — модель:
  - люди и роли;
  - `COLUMNS`, `phase(r)`, `progress(r)`, `statusText(r)`;
  - `turns(r)` — чей ход: `{p, text, mine, since|due, sla, ongoing, passive, h}`;
  - `visible`, `perms`, `canCheck`;
  - все действия в объекте `A`: `create`, `update`, `hrAccept/hrReturn`, `finApprove/finReturn/finReject`, `ceoApprove/ceoReject`, `assign`, `take`, `publish`, `addCandidate`, `move`, `feedback`, `reject`, `offer`, `accepted`, `check`, `started`, `decide`, `registered`, `finAccept`, `fot`, `cancel`, `addFiles`. Каждое пишет запись в `r.log` (история).
  - Демонстрационные данные (`seed`) собраны теми же действиями, поэтому история у них настоящая. Время событий сжато в рабочие часы.
- `Store` (в конце `model.js`) — состояние, `dispatch`, `setViewer`, `reset`. На это место потом встанет сервер.
- `js/ui.js` — `html`, иконки, `Btn`, `Field` (подпись и ошибка у поля), `Seg`, `useMenu`, `Decide` (решение с обязательным комментарием и строкой последствий), `Anim`.
- `js/board.js` — доска, карточки, сортировка (свой ход → просрочка → дольше ждёт), FLIP.
- `js/panel.js` — открытая заявка:
  - блок «ваш ход» (`MyTurn`) и «сейчас» (`Waiting`);
  - вкладки Путь / Кандидаты / Заявка / История;
  - карточка кандидата, добавление кандидата, отмена заявки.
- `js/form.js` — форма заявки (п. 4): черновик, отправка, доработка после возврата, защита несохранённого.
- `js/app.js` — адреса: `#/r/<id>`, `#/r/<id>/c/<cid>`, `#/r/<id>/add`, `#/r/<id>/edit`, `#/new`. Панель справа, Esc, возврат фокуса.
- Кэш: при правке файла поднимай `?v=` в `index.html`.
- **Ловушка Motion:** не анимируй `transform` к `'none'` — Motion превращает его в `scale(0)`. Пиши явное `translateX(0px)` / `scale(1)`.

## Проверка

```
python3 -m http.server 8765 &
PW=/opt/node-tools/node_modules/playwright node tests/flow.js /tmp/shots
PW=/opt/node-tools/node_modules/playwright node tests/roles.js /tmp/shots
```

- `flow.js` проходит заявку от создания до «Закрыто» по всем ролям: ошибки форм, возврат на доработку, кандидат, чек-листы, решение, ФОТ.
- `roles.js` снимает доску глазами каждой роли и телефон.
- Обе печатают ошибки консоли («no errors»).

ИИ-проверка по стандарту (быстрая, 15 пунктов) пройдена, находки P1 и P2 исправлены. Проверку человеком ещё не проводили.
